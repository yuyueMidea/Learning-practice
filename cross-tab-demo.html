前端跨标签页通信方案演示

用法：在浏览器里打开本文件，点「新开标签页」（或手动再开几个同样的标签页），在任一标签页发送消息，其他标签页会通过各方案收到并标注延迟。

附加：Web Locks 主标签页选举

跨标签页场景里常见需求是「只让一个标签页维护 WebSocket / 定时任务」。Web Locks 持有锁的标签页即为主标签页，关闭后锁自动释放，下一个标签页接任。

方案对比

方案原理范围实时性需持有窗口引用适用场景
BroadcastChannel同名频道广播同源即时否现代浏览器首选，简单直接
localStorage + storage 事件写入触发其他标签页的事件同源即时否需兼容老浏览器；登录态同步；只能传字符串；当前标签页自己不触发
SharedWorker多个页面连接同一个后台线程同源即时否共享连接、共享状态（如统一管理一个 WebSocket）；需要独立 worker 脚本
window.postMessage通过 window 引用定向发消息可跨源即时是（opener / window.open 返回值 / iframe）弹窗与父页面、跨域 iframe
IndexedDB 轮询写入数据库，其他标签页定时读取同源取决于轮询间隔否消息量大或需要持久化、可回溯
Cookie 轮询写 cookie，其他标签页定时读取同站取决于轮询间隔否古老方案，不推荐；约 4KB 限制，且每次请求都会带上
Service Worker（未内置演示）页面与 SW 之间 postMessage / Clients API同源即时否需要独立脚本且 HTTPS（或 localhost），适合离线/推送等场景
WebSocket / 服务端中转（未内置演示）经服务器转发可跨设备网络延迟否跨设备、跨浏览器同步
